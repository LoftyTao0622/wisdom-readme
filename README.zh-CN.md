# generate-readme

**从仓库证据出发，把 README 写得准确、自然，也让第一次阅读变得轻松。**

[English](./README.en.md) · [项目总览](./README.md)

## 适合谁

如果你要为一个真实仓库生成、重写、审计或本地化 README，这个 skill 会把“查事实、定结构、写内容、做验证”连成一条可复用路径。它不追求堆满徽章，而是让读者更快走到第一次成功操作。

## 快速开始

将 [`SKILL.md`](./SKILL.md) 和 [`references/`](./references/) 一起复制到编码助手的 skill 目录，然后提出目标：

```text
使用 generate-readme，重写当前项目的中英双语 README。
先给出最短可运行路径；用真实输出、截图或图示证明价值；
所有命令、版本和能力都必须能追溯到仓库证据。
```

输出应包含：项目定位、一个可信证明、主上手路径，以及经过事实和读者视角复核的细节。

## 工作流

```mermaid
flowchart LR
    A[读取意图与入口] --> B[建立证据地图]
    B --> C[选择阅读模式]
    C --> D[定位 / 证明 / 行动]
    D --> E[配置与参考细节]
    E --> F[事实、链接、语气复核]
```

| 阶段 | 关键问题 | 产出 |
|------|----------|------|
| 定位 | 这是什么，服务谁，带来什么结果？ | 一句话定位 |
| 取证 | 命令、版本、能力和关系能否追溯？ | 临时证据地图 |
| 设计 | 项目适合哪种阅读节奏？ | 结构与视觉模式 |
| 写作 | 新用户如何完成第一次成功操作？ | 一条连贯主路径 |
| 验证 | 事实、链接、层级和语气是否成立？ | 修正后的 README |

## 四种阅读模式

| 模式 | 适合项目 | 视觉重点 |
|------|----------|----------|
| **简约型** | 库、基础设施、源码仓库 | 定位、必要链接、最短入口 |
| **产品型** | 应用、开发工具 | 真实界面、输出或可复现结果 |
| **编辑型** | 创意工具、精选集合、教育项目 | 标题节奏、示例与留白 |
| **参考型** | API、SDK、多入口 CLI | 先选路径，再看精确用法 |

有多个真实读者路径时，skill 会用选择表标出推荐入口；只有一条路径时，保持线性阅读。

## 可调参数与不变原则

对于 skill 或提示词仓库，README 会把可调内容单独列出，例如版式、示例深度、语言版本或输出格式；同时保留保护来源、隐私和质量的核心原则。这样读者能知道哪里可以改，哪里不能凭想象扩展。

## 内容边界

不会读取或展示凭据、私有环境文件、日志、数据库转储、依赖目录、构建产物和版本控制内部文件。源码、清单、配置示例、路由注册和维护中的文档可以支持直接陈述；命名惯例、孤立 Dockerfile 或不完整实现不足以证明部署、性能或兼容性。

```text
├── SKILL.md                         # 工作流与约束

│   ├── design-and-structure.md      # 结构、视觉与导航
│   ├── evidence-and-scan.md         # 安全扫描与证据规则
│   └── verification.md              # 成稿复核清单
├── README.md                        # 双语入口
├── README.zh-CN.md                  # 中文说明
├── README.en.md                     # English guide
└── LICENSE
```

根目录是编辑源；`.agents/`、`.claude/`、`.codex/`、`.cursor/` 与 `.trae/` 保存平台副本。修改行为时先更新根目录，再同步副本。
